# 个性化学习路径规划与多模态资源生成设计

## 1. 文档定位

本设计文档用于补全联觉系统中“个性化学习路径规划 + 多模态资源生成 + 资源推送”的整体方案，重点回答以下问题：

- 在现有学习画像 Agent 已落地的前提下，后续多智能体系统如何继续扩展
- 为什么“个性化学习路径规划”是整个个性化生成项目的核心
- 多模态资源生成应如何围绕路径节点工作，而不是独立散点式产出
- 资源推送应如何与生成过程合并，形成“面向当前学生状态的一次性个性化生成与即时展示”

本方案默认参考以下已有文档：

- `（AI）智能体与工具输入输出收口设计.md`
- `docs/learning_profile_agent_workflow.md`
- 当前学生端 / 教师端前后端实现


## 2. 设计结论

当前项目里，真正需要作为核心能力重点建设的，不是“单独的资源推送模块”，而是“个性化学习路径规划 Agent”。

原因如下：

- 学习画像只负责回答“学生是谁、当前状态如何”，它不负责决定下一步学什么
- 多模态资源生成只负责回答“围绕当前学习任务应产出哪些资源”，它不负责决定先后顺序
- 资源推送本质上不是一个独立业务闭环，而是路径规划结果的前端呈现动作
- 对于本赛题，真正体现“个性化”和“提升学习效率”的关键，不是资源种类堆叠，而是是否能根据学生画像、课程结构、知识短板和学习目标，动态给出一条合理的学习路径

因此，本项目后续应采用：

- 画像先行
- 路径为核
- 资源围绕路径节点生成
- 生成完成后直接展示给学生
- 学生新行为再反向更新画像和路径

一句话概括：

> 画像决定“这个学生现在是什么状态”，路径决定“他接下来该怎么学”，资源决定“每一步给他什么学”。


## 3. 赛题要求映射

结合赛题要求，系统能力应映射为 3 个主模块。

### 3.1 对话式学习画像自主构建

对应当前已基本落地的学习画像 Agent。

当前已有基础：

- 对话输入
- 学习记录输入
- 答题记录输入
- 资源使用输入
- `personal_syllabus` 上下文读取
- 六维以上画像标签输出
- `confidence`、`evidence`、`recent_anomaly` 等解释性字段

当前画像输出可直接作为下游标准输入契约，不再由资源模块重复做学生理解。

### 3.2 多智能体协同的资源生成

资源生成不能作为单一“大模型直接出材料”的黑盒，而应体现多智能体协同：

- 主 Agent 负责任务编排与结果收口
- 路径规划 Agent 决定资源生成目标
- 统一资源生成 Agent 负责多类型资源生成
- 审核 Agent 负责事实校验和内容安全
- 学习效果评估 Agent 负责结果回流与下一轮调优

### 3.3 个性化学习路径规划和资源推送

本模块应成为整个项目主轴。

系统不是先“无差别生成很多资源”再尝试推荐，而是：

1. 先确定当前学习阶段
2. 再确定阶段内的知识顺序
3. 再确定当前节点需要哪些资源
4. 资源生成完成后直接作为本轮个性化结果展示给学生
5. 学生产生新行为后再调整路径


## 4. 总体架构

### 4.1 角色划分

建议采用 1 个主 Agent + 5 个业务 Agent 的结构。

#### 1）总调度决策 Agent

定位：

- 全局唯一调度中枢
- 不直接生成教学内容
- 负责调用其他 Agent、排序、异常回退、输出统一结构

职责：

- 接收学生请求或系统事件
- 判断是“初始化学习”“继续学习”“生成资源”“路径重规划”“效果评估”
- 驱动各子 Agent 按顺序执行
- 输出前端可直接渲染的统一结果

#### 2）学习画像构建 Agent

定位：

- 当前已实现的结构化画像编排器

职责：

- 生成或更新学生画像
- 输出标准化画像 JSON

注意：

- 只负责“描述学生状态”
- 不直接生成路径和资源

#### 3）个性化学习路径规划 Agent

定位：

- 后续最核心的新增 Agent

职责：

- 读取学生画像
- 读取课程 syllabus / knowledge graph / personal_syllabus
- 推演当前应学阶段、下一步知识点顺序、节点难度与完成标准
- 输出动态学习路径

这是整个项目的核心业务中枢。

#### 4）统一个性化多模态资源生成 Agent

定位：

- 围绕“当前路径节点”生成多类型学习资源

职责：

- 根据路径节点和画像，生成至少 5 类资源
- 资源类型可按课程形态进行裁剪，但整体项目至少覆盖：
  - 专业课程讲解文档
  - 知识点思维导图
  - 不同类型练习题目
  - 拓展阅读材料
  - 多模态视频 / 动画脚本
  - 代码类实操案例
  - 实践项目学习材料

说明：

- 资源默认面向学生当前状态即时生成
- 生成完成后由主 Agent 直接组织展示
- 资源生成结果服务当前学习路径节点，而不是脱离路径独立存在

#### 5）内容安全与防幻觉审核 Agent

定位：

- 所有资源出站前的统一审核层

职责：

- 检查内容是否偏离课程边界
- 检查引用知识是否与图谱 / syllabus / RAG 证据一致
- 检查表述是否合规、安全、无明显幻觉

#### 6）学习效果评估 Agent

定位：

- 学习闭环优化器

职责：

- 读取学习记录、答题结果、资源完成情况、问答行为
- 评估本轮路径是否有效
- 输出路径调整建议与下一轮资源偏移策略


## 5. 为什么“路径规划”必须成为核心

### 5.1 资源本身不能解决顺序问题

赛题要求的不只是“能生成资源”，而是“提升学习效率、优化资源利用、增强学习效果”。

如果没有路径层，系统只能做到：

- 看到薄弱点就生成一份材料
- 看到提问就生成一份解释
- 看到学习目标就生成一份资源包

这样的问题是：

- 不知道先学哪个知识点
- 不知道哪些知识点是前置依赖
- 不知道学生应先补基础还是直接进阶
- 不知道资源应该在什么时间点展示

所以路径层必须先解决“顺序、阶段、优先级、完成标准”。

### 5.2 画像是静态截面，路径是动态策略

画像回答的是：

- 当前掌握度
- 当前偏好
- 当前风险

路径回答的是：

- 先补什么
- 再学什么
- 哪一步需要强化练习
- 哪一步适合生成项目或视频资源

画像没有路径，就只是分析结果；路径拿到画像，才能变成学习行动方案。

### 5.3 推送本质上是路径当前节点的展示动作

本项目中，资源推送不必单独设计成复杂推荐系统。

更合理的定义是：

- 当前路径节点被主 Agent 选中后
- 统一资源生成 Agent 产出该节点对应的个性化资源包
- 主 Agent 将本轮结果直接组织为前端展示内容

也就是说：

- 规划决定“推什么”
- 生成决定“生成什么样”
- 展示决定“学生看到什么”


## 6. 核心业务闭环

整体闭环建议统一为：

1. 学生进入课程
2. 主 Agent 调用学习画像 Agent 获取当前画像
3. 主 Agent 调用路径规划 Agent 生成当前动态学习路径
4. 主 Agent 选取“当前最优路径节点”
5. 主 Agent 调用多模态资源生成 Agent 生成该节点资源包
6. 主 Agent 调用审核 Agent 完成内容检查
7. 资源结果直接展示给学生
8. 学生进行学习、提问、答题、提交学习记录
9. 学习效果评估 Agent 更新评价结果
10. 画像 Agent 增量更新画像
11. 路径规划 Agent 重新规划下一步

这是一个“随学随新”的动态闭环，不是一次性静态推荐。

## 8. 个性化学习路径规划 Agent 详细设计

### 8.1 定位

该 Agent 是连接“画像”和“资源”的中间决策层。

它不直接负责生成最终学习材料，但它决定：

- 学习先后顺序
- 当前节点优先级
- 当前节点适合的资源类型组合
- 节点完成标准
- 何时进入下一节点

### 8.2 输入信号

建议至少消费以下四类信号：

#### 1）目标信号

- `learning_goal`
- `target_level`
- `deadline`

#### 2）能力信号

- `knowledge_mastery`
- `concept_gaps`
- `practice_ability`
- `comprehension_level`

#### 3）行为与风险信号

- `study_frequency`
- `study_duration`
- `attention_pattern`
- `dropout_risk`
- `recent_anomaly`

#### 4）偏好信号

- `learning_style`
- `resource_preference`
- `difficulty_tolerance`

### 8.3 路径推演逻辑

建议采用“知识依赖 + 画像缺口 + 时间约束 + 风险约束”的综合打分。

可将每个候选知识节点计算一个优先级分数：

```text
priority_score =
  goal_relevance
  * prerequisite_criticality
  * weakness_weight
  * time_urgency_weight
  * preference_fit_weight
  - overload_penalty
```

其中：

- `goal_relevance`：与当前学习目标相关程度
- `prerequisite_criticality`：作为后续前置知识的关键程度
- `weakness_weight`：画像显示的薄弱程度
- `time_urgency_weight`：距离阶段目标截止时间的紧迫性
- `preference_fit_weight`：与学习风格和资源偏好的适配度
- `overload_penalty`：对当前学生认知负担过高时的惩罚项

### 8.4 路径输出层级

建议路径不是只有“周次顺序”，而是三层结构：

#### 层 1：阶段

例如：

- 基础补齐
- 核心掌握
- 强化练习
- 实操迁移
- 项目应用

#### 层 2：节点

例如某一阶段中的具体知识点或任务：

- 函数参数
- 循环嵌套
- 条件控制
- SQL 查询基础

#### 层 3：节点内资源包

例如针对某节点生成：

- 文档讲解
- 思维导图
- 题库
- 视频脚本
- 代码案例

### 8.5 动态更新触发器

以下事件发生时，应触发路径重规划或局部调整：

- 学生提交新对话
- 学生完成学习记录
- 学生答题结果明显变化
- 学生提问暴露新的薄弱点
- 学生资源使用偏好改变
- 学习效果评估 Agent 判断当前路径不再适合


## 9. 多模态资源生成 Agent 设计

### 9.1 核心原则

该 Agent 不是“我想生成什么就生成什么”，而是严格围绕路径节点工作。

它的资源生成目标必须来自路径规划 Agent，而不是自己决定学习重点。

### 9.2 建议覆盖的资源类型

为满足赛题要求，建议系统在答辩与演示中至少稳定展示以下 5 种以上类型：

- 专业课程讲解文档
- 知识点思维导图
- 单选 / 判断 / 简答题库
- 拓展阅读材料
- 多模态教学视频 / 动画脚本
- 代码实操案例
- 实践项目学习材料

### 9.3 资源生成与展示策略

建议采用“当前节点资源包”模式：

- 每次围绕当前节点生成一组资源
- 生成完成后直接展示在学生端
- 展示结果就是本轮个性化资源推送结果
- 学生继续学习后，下一轮再围绕新节点生成新的个性化资源包

这比“预先生成大量资源再做推荐”更符合赛题的时效性和个性化要求。

### 9.4 与现有代码的衔接

当前 `tasks/student_resource_task.py` 已经具备资源生成雏形，可将其升级为统一资源生成 Agent 的执行层。

建议后续改造方向：

- 保留现有资源类型定义机制
- 从“仅按 week_indices 生成”升级为“按路径节点生成”
- 输入从 `week_indices` 扩展为 `path_node + profile_summary + graph_context`
- 输出从“文件列表”扩展为“资源包结构”


## 10. 审核 Agent 设计

审核 Agent 应位于所有资源结果出站前。

建议检查项：

- 内容是否脱离课程 syllabus 边界
- 内容是否与图谱检索结果冲突
- 是否出现明显幻觉性表述
- 是否包含不合规内容
- 难度是否与当前学生画像严重不匹配

审核结果建议输出：

```json
{
  "approved": true,
  "risk_level": "low",
  "issues": [],
  "fix_suggestions": []
}
```

如未通过，可回退给资源生成 Agent 重写局部内容，而不是整轮报错。


## 11. 学习效果评估 Agent 设计

### 11.1 定位

该 Agent 负责把“学生是否真的学会了”反馈回系统。

### 11.2 关键输入

- 学习时长
- 资源查看与完成情况
- 题目作答结果
- 提问深度变化
- `personal_syllabus.competance` 变化
- 学习画像前后变化

### 11.3 关键输出

- 当前节点是否完成
- 本轮资源是否有效
- 是否应降低难度
- 是否应增加练习
- 是否应进入下一节点
- 是否应重新规划路径

### 11.4 与现有系统衔接

当前学生端已有：

- 学习记录填写
- 提问
- `personal_syllabus` 更新

这些都可以作为评估 Agent 的可用输入，不需要从零起步。


## 12. 前端产品设计建议

你前面提到“个性化资源生成还未实现前端”，从业务上建议不要单独做一个“资源推送页面”，而是将其嵌入学生学习主界面。

建议学生端新增 3 个核心区块。

### 12.1 当前学习路径区

展示：

- 当前阶段
- 当前节点
- 已完成节点
- 下一节点
- 每个节点的完成标准

### 12.2 本轮个性化学习包区

展示：

- 当前节点自动生成的文档
- 思维导图
- 题库
- 视频 / 动画脚本
- 代码案例 / 项目材料

这里的“展示结果”就是本轮资源推送结果。

### 12.3 调整与反馈区

展示：

- 我已看完 / 我还不懂 / 太难了 / 太简单了
- 提问入口
- 学习记录入口

这些反馈直接进入评估 Agent 与画像 Agent，形成下一轮路径更新。

## 15. 与现有项目的对接关系

### 15.1 已有能力

- 学习画像 Agent 已落地
- `personal_syllabus` 已具备学生个性化进度容器能力
- RAG / 图谱检索链路已存在
- 学生问答链路已存在
- 学生资源生成任务已有雏形

### 15.2 当前缺口

- 还没有真正落地的“路径规划 Agent”
- 资源生成尚未严格围绕路径节点
- 学生端还没有“学习路径 + 本轮资源包”联动展示
- 审核 Agent 与评估 Agent 还未成型

### 15.3 最优落地顺序

建议按下面顺序推进：

1. 先落地路径规划 Agent
2. 再将资源生成从“按周生成”改为“按路径节点生成”
3. 再补学生端当前路径与本轮学习包展示
4. 再接入审核 Agent
5. 最后补学习效果评估 Agent 与动态重规划

## 17. 最终方案表述

如果要对外描述这个项目，建议统一表述为：

> 联觉系统基于“学习画像构建 Agent - 个性化学习路径规划 Agent - 多模态资源生成 Agent - 内容审核 Agent - 学习效果评估 Agent”的多智能体协同架构，围绕学生当前课程目标、知识短板、学习进度与风格偏好，动态生成个性化学习路径，并按当前路径节点即时生成和展示多模态学习资源，从而实现更高效的学习支持闭环。

进一步压缩成一句答辩式表达：

> 我们不是先生成一堆资源再推荐，而是先规划学生当前最该学的路径节点，再围绕该节点即时生成本轮个性化学习资源并直接展示给学生。


## 18. 本文档给当前项目的直接指导

对当前联觉系统，最重要的设计决策是：

- 把“路径规划 Agent”作为下一阶段核心
- 把“资源推送”并入“当前路径节点资源包展示”
- 把“统一资源生成 Agent”定位为路径节点执行器
- 把“画像、问答、学习记录、资源使用”全部收回到路径动态更新闭环中

这样做既贴合你现有代码基础，也最符合赛题核心要求。
