# 1 项目概述

## 1.1 项目背景

高等教育正在从统一进度、统一资源、统一评价的教学方式，转向面向学习者差异的个性化学习支持。学生在知识基础、学习目标、认知风格、学习节奏和易错点上存在明显差异，传统教学资源和基础问答工具难以持续感知学生状态，也难以把“诊断、推荐、学习、练习、反馈、调整”组织成稳定闭环。

大模型、RAG、多模态资源生成和多 Agent 协同为这一问题提供了新的工程路径。系统可以在学生自然语言交互中抽取画像，结合课程大纲和知识库进行路径推荐，为当前学习步骤生成不同形态的资源，并在学习反馈后更新学习计划和成长树，从而形成可追踪、可解释、可持续优化的学习辅助系统。

## 1.2 项目定位

本项目定位为面向高校课程学习的个性化学习辅助多 Agent 系统。系统不是单一聊天机器人，也不是单一资源生成工具，而是围绕学习目标提供一套完整后端闭环：

- 学习画像：理解学生基础、目标、偏好和薄弱点。
- 路径推荐：基于课程结构、画像和学习状态生成个性化学习计划。
- 资源生成：围绕当前步骤生成文档、测验、思维导图、编程练习、PPT 等资源。
- 即时答疑：区分概念解释、学习策略和练习帮助，并返回结构化答案。
- 成长树：记录学生真实触达、练习、薄弱和掌握的知识节点。
- Total Agent：统一编排上下文读取、意图识别、工具调用、资源生成和反馈闭环。

## 1.2.1 应用场景

典型应用场景包括：

- 学生输入学习目标后，系统推荐个性化学习路径。
- 学生在当前学习步骤中请求资料、练习或总结，系统生成对应资源。
- 学生提出概念问题或“下一步怎么学”的策略问题，系统根据计划、画像和证据生成结构化回答。
- 学生完成资源学习后提交反馈，系统更新学习计划并同步成长树。
- 教师或平台查看课程层面的弱点摘要，用于辅助教学调整。

## 1.2.2 目标人群

主要目标用户：

- 高校学生：希望获得个性化学习路径、针对性资源和即时学习指导。
- 任课教师：希望掌握学生薄弱点、资源使用情况和课程学习状态。
- 教学平台运营方：希望将大模型能力接入课程学习闭环，而不是只提供聊天式问答。

## 1.3 项目方案

系统采用“总 Agent 编排 + 专项 Agent/工具闭环”的方案。Total Agent 作为统一入口，读取用户、课程、画像、计划、资源、成长树和 RAG 证据后，根据用户意图分派到对应能力：

- 推荐学习路径。
- 接受学习计划并激活当前步骤。
- 生成当前步骤资源。
- 回答学习问题。
- 记录学习反馈。
- 跳过或调整当前步骤。

专项模块保持明确边界。学习画像负责状态建模，推荐模块负责路径选择，资源生成模块负责多形态资源产物，成长树负责学生真实学习状态，Total Agent 负责流程调度和结构化返回。

## 1.4 项目目标

项目目标分为功能目标和工程目标。

功能目标：

- 支持自然语言输入学习目标和学习问题。
- 支持动态学习画像构建和读取。
- 支持个性化路径推荐与学习计划落盘。
- 支持围绕当前步骤的多类型资源生成。
- 支持即时答疑和学习策略建议。
- 支持学习反馈驱动计划和成长树更新。

工程目标：

- 后端模块边界清晰，具备可测 E2E 闭环。
- Agent 输出结构化，便于前端展示和测试断言。
- 对 RAG 低相关、无 active plan、缺少目标等情况提供可解释降级。
- 保持开发文档、测试报告和模块 dev doc 与代码一致。

## 1.5 项目价值

项目价值体现在三个层面：

- 对学生：降低资源筛选成本，获得更贴合自身状态的学习路径、资料、练习和答疑。
- 对教师：通过聚合弱点和学生成长树了解学习过程，而不是只看最终成绩。
- 对平台：把大模型能力从“问答插件”升级为可编排、可追踪、可演示的学习多 Agent 后端。
