# 8 部署与运行环境

## 8.1 运行环境

本系统采用前后端分离部署方式。后端服务以 Python Web 服务形式运行，负责用户、教学内容、学习画像、学习路径推荐、资源生成、学习成长树和多 Agent 调度等业务；前端服务负责页面展示和用户交互；持久化层由关系数据库、图数据库/检索服务和文件存储共同组成。

表 8-1 运行环境建议

| 环境项 | 建议配置 | 说明 |
| --- | --- | --- |
| 操作系统 | Linux 服务器或 WSL/Linux 兼容环境 | 开发和调试环境可使用 WSL；正式部署建议使用 Linux 服务器或容器环境。 |
| Python 环境 | Conda 独立环境，项目环境名为 lianjue | 当前调试环境使用 `conda activate lianjue`。 |
| Python 版本 | Python 3.11 或兼容版本 | 以依赖安装和运行测试通过的解释器版本为准。 |
| Web 框架 | Flask | `run.py` 为后端服务启动入口。 |
| 数据库 | MySQL | 默认配置库名示例为 `knowlion`，正式部署可按环境规划调整。 |
| 图数据库/检索服务 | AbutionGraph / KnowLion | 用于教学知识图谱构建、RAG 检索和图谱相关能力。 |
| 模型服务 | OpenAI-compatible API Provider | 项目通过统一模型配置适配文本模型、视觉模型和向量模型。 |
| 文件存储 | 本地文件系统或挂载目录 | 用于教学材料、解析产物、生成资源、学习画像和运行日志等文件。 |
| 前端运行环境 | Node.js 构建环境与静态资源服务 | 前端独立构建，通过 API Base URL 访问后端服务。 |

后端代码运行时会在应用启动阶段初始化 Flask 应用、注册 API 蓝图、连接 MySQL，并通过 SQLAlchemy 创建或补齐必要的数据表。后台文档处理任务由 `JobChecker` 轮询执行，默认随 `run.py` 一并启动。

## 8.2 系统配置

系统配置以项目根目录下的 `config.json` 为准。若该文件不存在，程序会回退读取 `config.example.json`，但示例配置仅用于说明字段结构，不应直接作为正式运行配置使用。正式部署前应复制示例配置并补齐真实连接信息、模型密钥和存储路径。

表 8-2 核心配置项

| 配置区域 | 主要字段 | 用途 |
| --- | --- | --- |
| MODEL_CONFIGS.text | model_name、api_base、api_key | 文本生成、Agent 推理、学习反馈分析等能力。 |
| MODEL_CONFIGS.image | model_name、api_base、api_key | 多模态理解、图片内容处理等能力。 |
| MODEL_CONFIGS.embed | model_name、api_base、api_key、encoding_format | 文本向量化、检索增强和相似度计算。 |
| ABUTION_CONFIG | abution_url、username、password、batch_size | 连接国产时序动态图数据库/检索服务。 |
| PROCESSING_CONFIG | save_md、save_triples、device_mode、MODEL_PATH | 控制文档解析、三元组产物、Docling 模型路径和处理资源。 |
| MYSQL | host、port、user、password、database | 后端业务数据库连接。 |

除配置文件外，MySQL 连接也支持从环境变量读取。常用环境变量包括 `MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_HOST`、`MYSQL_PORT` 和 `MYSQL_DATABASE`。当配置文件未提供对应字段时，程序会尝试使用环境变量作为补充。

测试环境中可按需开启真实外部依赖调用。常用测试开关如下：

| 环境变量 | 含义 |
| --- | --- |
| RUN_LLM_TESTS | 允许执行真实大模型调用相关测试。 |
| RUN_REAL_RAG_TESTS | 允许执行真实图数据库/RAG 检索测试。 |
| RUN_DB_TESTS | 允许执行真实数据库读写测试。 |

## 8.3 部署方案

系统部署可划分为前端访问层、后端服务层和持久化/外部能力层。前端访问层负责页面资源发布和用户请求转发；后端服务层承载业务 API、总 Agent 调度、资源生成和后台任务；持久化/外部能力层提供 MySQL、图数据库/检索服务、模型 API 和文件存储。

表 8-3 部署节点职责

| 部署节点 | 主要职责 | 典型部署方式 |
| --- | --- | --- |
| 前端静态服务 | 提供学生端和管理端页面，配置 API Base URL | Nginx、静态资源托管或前端开发服务器。 |
| 后端 API 服务 | 提供 `/api/*` 接口、SSE 流式输出和业务编排 | Python 进程、进程管理器或容器服务。 |
| 后台任务线程 | 轮询文档处理 Job，执行文件解析、三元组生成和图谱写入 | 默认随 `run.py` 启动，也可通过参数关闭。 |
| MySQL | 保存用户、课程、大纲、材料、计划、Agent 状态等结构化数据 | 独立数据库实例或托管数据库。 |
| 图数据库/检索服务 | 保存和检索课程知识图谱、RAG 证据 | 独立服务进程或专用服务器。 |
| 文件存储 | 保存上传文件、解析产物、生成资源、日志和学习画像文件 | 本地目录、挂载磁盘或对象存储适配层。 |
| 模型服务 | 提供文本、视觉和向量模型推理能力 | 云服务 API 或兼容 OpenAI 协议的模型网关。 |

后端部署流程如下。

第一步，准备 Python 运行环境。建议使用独立 Conda 环境或容器镜像固定依赖，避免与系统 Python 或其他项目依赖冲突。当前项目环境名为 `lianjue`，可在进入项目目录后激活该环境。

第二步，安装项目依赖。依赖清单位于 `requirements.txt`，包括 Flask、SQLAlchemy、PyMySQL、LiteLLM、pydantic-ai、Docling、EasyOCR、pypdf、python-pptx、pandas、matplotlib 等后端运行和文档处理依赖。涉及 PDF、PPT、中文字体或 LaTeX 转换的部署环境，还应安装 Pandoc、TeX Live 相关组件和中文字体。

第三步，准备配置文件。将 `config.example.json` 复制为 `config.json`，按实际环境填写 MySQL、AbutionGraph/KnowLion、模型 API 和文档处理配置。正式环境应避免将真实密钥提交到代码仓库。

第四步，准备外部服务。启动 MySQL，确认目标数据库可连接；启动 AbutionGraph/KnowLion 服务，确认图数据库地址、账号和密码可用；确认模型 API 网络可达，并具备文本、视觉和向量模型的调用权限。

第五步，准备运行目录。后端运行过程中会读写 `pdfs`、`markdowns`、`triples`、`knowledge`、`material`、`schedule`、`generative`、`study_graph`、`study_buddy`、`profiles`、`history`、`logs` 等目录。部署账号应具备这些目录的读写权限。若使用挂载盘或容器卷，应保证路径在服务重启后仍然可用。

第六步，启动后端服务。推荐以 `run.py` 作为统一入口启动后端服务。常用启动参数见表 8-4。

表 8-4 后端启动参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| --host | 0.0.0.0 | Flask 服务监听地址。 |
| --port | 5000 | Flask 服务监听端口。 |
| --debug | false | 是否启用 Flask 调试模式，正式环境不建议开启。 |
| --no-job-checker | false | 只启动 API 服务，不启动后台 JobChecker。 |
| --workers | 2 | 后台文档处理并行线程数。 |
| --input | ./pdfs | 后台文档处理输入目录。 |

后端启动命令示例为：`python run.py --host 0.0.0.0 --port 5000`。若只需要调试 API，不希望后台任务轮询执行，可使用：`python run.py --no-job-checker`。

前端部署时，应先完成前端项目构建，并在前端环境配置中设置后端 API Base URL。长耗时功能，例如资源生成、知识构建和 Agent 流式回答，应通过状态轮询、SSE 或前端状态事件展示执行进度，避免用户误认为请求无响应。

## 8.4 外部依赖

系统运行依赖分为基础服务依赖、模型服务依赖、文档处理依赖和前端构建依赖。

基础服务依赖包括 MySQL、AbutionGraph/KnowLion 和文件存储。MySQL 保存核心业务数据和 Agent 运行时状态；图数据库/检索服务提供知识图谱构建和 RAG 检索能力；文件存储保存上传材料、解析文件、生成资源、学习画像、聊天历史和运行日志等内容。

模型服务依赖包括文本模型、视觉模型和向量模型。文本模型用于总 Agent 调度、学习画像分析、推荐解释、资源生成和学伴对话；视觉模型用于图片或多模态材料理解；向量模型用于检索增强、语义匹配和相关性计算。项目配置采用 OpenAI-compatible 接口形式，便于替换不同模型提供方。

文档处理依赖包括 Docling、EasyOCR、pypdf、Pandoc、TeX Live、中文字体和 Office 文档处理相关库。为避免首次运行时临时下载模型或缺少系统组件，正式部署建议在镜像构建或服务器初始化阶段预先安装系统依赖，并将 Docling 所需模型放置到 `PROCESSING_CONFIG.MODEL_PATH` 指定目录。

前端构建依赖由前端工程独立管理。后端文档仅要求前端能够访问后端 `/api/*` 接口，并支持普通 HTTP 请求、文件上传下载、轮询接口和流式响应展示。

## 8.5 运行维护

系统运行维护重点包括服务可用性、日志留存、数据库备份、文件备份和外部服务连通性。

后端服务日志默认写入 `logs/service.log`，采用按日滚动方式保留。总 Agent 和工具调用链路可通过专用调试日志辅助排查，重点观察工具入参、工具返回、当前计划状态、候选推荐状态和流式终止工具序列。正式部署时应根据服务器磁盘容量设置日志保留周期，并避免在日志中输出明文密钥。

MySQL 应纳入常规备份策略。建议至少备份用户数据、课程数据、材料索引、学习计划、推荐快照、Agent 会话状态和学习反馈记录。文件存储目录应与数据库备份保持一致的时间点或具备可追溯版本，否则可能出现数据库记录存在但文件产物缺失的情况。

图数据库/检索服务应保持与课程材料处理流程的一致性。教学材料更新、知识图谱构建任务完成后，应检查图谱数据是否可查询，必要时通过 RAG 评测脚本验证召回率、准确率、幻觉率和检索速度。

模型服务应关注 API 配额、调用延迟、失败重试和网络稳定性。对于资源生成和多 Agent 调度这类长链路任务，应在业务层保留状态记录，避免单次模型调用失败导致用户无法恢复上下文。

## 8.6 移动端或手机端说明

当前系统不将手机端侧部署作为独立部署形态。学生用户可通过移动端浏览器访问前端页面，但移动端适配属于前端展示层能力，不改变后端部署结构。

若后续正式支持移动端，应补充验证以下内容：移动端浏览器兼容性、响应式布局、文件预览和下载体验、学习资源阅读体验、答题交互体验、成长树小屏折叠展示方式，以及 SSE 或轮询状态在弱网环境下的恢复能力。
