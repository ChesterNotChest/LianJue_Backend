# 11 开发计划与风险控制

## 11.1 最终呈现形式

最终建议呈现为 Web 应用：

- 学生学习工作台。
- 多 Agent 状态流。
- 学习路径与当前 step。
- 多模态资源展示。
- 即时答疑面板。
- 学习成长树。
- 教师或课程聚合摘要视图。

## 11.2 当前完成情况

后端：

- 学习画像闭环已形成。
- 推荐路径与 learning plan 闭环已形成。
- 资源生成闭环已形成。
- Study Graph 读写和 features 已形成。
- Total Agent 编排和即时答疑结构化已形成。
- E2E 统一入口已形成。

前端：

- 已有 Web，但需要向生产级学习工作台和多 Agent 演示体验升级。

## 11.3 后续进度安排

建议阶段：

1. 前端信息架构收口：确定主学习工作台、资源页、答疑页、成长树页。
2. 接入 Total Agent 结果：展示 `result`、`tool_status_events`、`suggested_next_action`。
3. 资源展示优化：按 resource type 做专门 UI。
4. 成长树可视化：从 Study Graph tree/features 渲染节点状态。
5. 演示路径打磨：准备一条稳定的课程和用户数据。
6. 文档和 PPT 收口：补图、补截图、补测试结果。

## 11.4 关键问题

关键风险：

- 真实 RAG 命中质量不稳定。
- 真实 LLM 输出存在结构漂移。
- 多类型资源展示对前端要求较高。
- 演示数据如果不稳定，会削弱多 Agent 闭环效果。
- 文档如果脱离真实代码，容易和实现不一致。

应对策略：

- 保持默认 E2E 和 opt-in E2E 分层。
- 对 QA 和资源 payload 做结构化校验。
- 对 RAG 低相关进行 warning 降级。
- 准备稳定演示 fixture。
- dev doc 作为唯一模块事实源。
