# 个人成长学习树 概要设计

## 1. 背景与目标

本系统的核心目标是把“每个学生自己的学习轨迹”沉淀为一棵可持续生长的个人成长学习树，同时保留一套面向全体学生的总知识库与总学习树。系统通过“总 agent + 个人 agent”的双层协作机制，让个人学习行为反哺总库，总库的知识组织方式再反过来优化个人学习路径。

设计上强调四件事：

1. 个人有独立的学习画像、掌握度、薄弱点和历史提问轨迹。
2. 全局有统一的课程大纲、知识图谱、教学材料和推荐策略。
3. agent 与工具解耦，agent 负责推理与决策，工具负责检索、解析、存储和回写。
4. 数据必须可追踪，所有学习行为都能回溯到时间、周次、材料和知识节点。

## 2. 总体架构

系统可拆为五层：

### 2.1 前端层

前端负责学生端和教师端的操作入口，主要发起以下动作：

- 上传教学日历、教学材料、图谱文件
- 创建和维护图谱
- 初始化个人 syllabus
- 提问、查看回答、查看个人学习树
- 查看学习画像和推荐建议

### 2.2 API 层

后端通过 Flask blueprint 暴露统一接口，承担请求分发和参数校验。

- 用户接口：登录、注册、信息维护
- 教学大纲接口：草稿生成、终稿构建、更新、查询
- 学习接口：个人 syllabus 初始化、问答、进度更新
- 文件接口：文件上传、列表、详情
- 图谱与作业接口：图谱创建、job 创建、暂停、恢复、结束、查询
- 学习画像接口：聚合用户历史、学习记录和资源使用情况

### 2.3 Agent 层

建议将智能体分成三类：

- 总 teacher agent：观察全局学生行为，发现共性难点，调整总知识库和推荐策略。
- 个人 student agent：面向单个学生，基于个人学习树给出个性化回答和下一步建议。
- 学习画像 agent：从历史问答、学习时长、资源偏好和掌握度中抽象出学习画像。
- 资源推荐 agent：一个多模态推荐智能体，基于个人画像、课程周次、知识薄弱点、群体偏好以及文本/图片/音频/视频等资源特征，为学生输出下一步最适合的资料、题目、视频、图示或补充阅读。

### 2.4 工具层

工具层负责提供 agent 的“动作能力”：

- 文档解析：PDF、OCR、Markdown、Docling 等
- 图谱检索：KnowLion / AbutionGraph，未来可替换为 RepoDory
- 向量检索与语义检索
- JSON 文件读写与历史窗口管理
- MySQL 读写与关系绑定
- 工具层还负责把执行结果、错误信息、资源元数据和状态变化回传给 agent，供下一步决策使用

### 2.5 存储层

系统当前采用多种存储协同：

- MySQL：用户、课程、文件、图谱、job、学习绑定关系
- 文件系统：教学日历、syllabus 草稿、final syllabus、个人 syllabus、历史记录
- 图数据库：知识节点、三元组、关系图、检索结果

## 3. 业务对象定义

### 3.1 总知识库

总知识库保存面向全体学生的课程结构、知识图谱和教学材料。它的重点是“知识组织”和“知识检索”，不直接包含某个学生的个体画像。

### 3.2 个人成长学习树

个人成长学习树是学生级别的数据结构，核心字段包括：

- 学生所属 syllabus
- 每周内容与增强内容
- 掌握度 competance
- 掌握度进度 competance_progress
- 学习建议 suggested_competance_list
- 更新时间 updated_at
- 提问历史与回答历史
- 学习时长和学习行为记录

### 3.3 教学大纲

教学大纲分为草稿和终稿两阶段：

- 草稿：从教学日历生成，强调结构化周次内容
- 终稿：在图谱检索增强后生成，形成可直接供问答与推荐使用的课程知识底座

### 3.4 教学材料

教学材料由教学大纲派生，用于题目生成、知识点补充、复习建议和资源推荐。

### 3.5 资源推荐 agent

资源推荐 agent 不是简单的检索模块，而是一个面向学习路径优化的多模态决策层。它会综合以下输入：

- 个人 syllabus 中的掌握度、进度和薄弱周次
- 学习画像中的风格、频率和偏好
- 总 syllabus 中每周的增强内容和教学重点
- 图谱和材料库中的相关资源
- 资源本身的模态信息，如文本、图片、流程图、音频、视频、课件截图和题目截图

它的输出一般包括：

- 推荐学习材料
- 推荐复习顺序
- 推荐题型和练习难度
- 推荐补充知识节点
- 推荐多模态资源组合，例如“先看视频，再看图解，再做题”
- 推荐适合当前知识点的可视化材料、讲解片段或题目截图

### 3.6 job

job 是文档处理流水线的执行单元，用来跟踪文件从解析到知识落盘的全过程。

## 4. 核心工作流

### 4.1 总库构建流程

1. 前端上传教学日历或教学材料。
2. 后端将文件写入文件系统，并登记到 MySQL。
3. 创建 graph，将文件绑定到图谱。
4. job 进入文档处理流水线。
5. 文档先解析为 Markdown，再转三元组，再转知识，再写入图谱或知识存储。
6. 教学大纲草稿和终稿在检索增强后生成。
7. 总库沉淀为课程级别的知识结构。

### 4.2 个人库初始化流程

1. 学生选择课程后，调用个人 syllabus 初始化接口。
2. 系统从总 syllabus 克隆周次结构。
3. 为每个周次补充个人字段，如 competance、progress、suggested_competance_list。
4. 将个人 syllabus 路径写入 user_syllabus 关系表。
5. 学生后续所有行为都在这棵个人树上累积。

### 4.3 提问问答流程

1. 学生发起提问。
2. student agent 先读取个人 syllabus，确定当前周和当前掌握度。
3. 再从总 syllabus 中找相关周次。
4. 基于相关周次的增强内容调用图谱检索。
5. 将问题、周次、RAG 结果和当前掌握度一起送入 LLM。
6. 返回回答、引用文档和建议周次。
7. 回写历史窗口和个人掌握度变化。

### 4.4 学习画像流程

1. 聚合历史提问、回答记录、学习时长、资源使用和答题记录。
2. 识别学习风格、频率、偏好、薄弱主题和风险水平。
3. 输出学习画像供 teacher agent 和资源推荐 agent 使用。
4. teacher agent 结合多个学生画像，反向调整总库结构。
5. 资源推荐 agent 根据个人画像和总库策略，生成个性化资源清单和学习路径。

## 5. Agent 间数据流

### 5.1 个人 agent 到总 agent

个人 agent 在处理学习行为时，会向总 agent 提供以下信号：

- 该学生常问的周次和主题
- 回答中频繁出现的困难点
- 学习时长与提问密度
- 掌握度变化趋势
- 常用资料类型和检索路径

### 5.2 总 agent 到个人 agent

总 agent 根据群体行为调整：

- 推荐哪些知识节点优先出现
- 哪些周次需要补强说明
- 哪些材料更适合某类学生
- 哪些提示语更容易促进学习

### 5.3 画像 agent 的中介作用

画像 agent 既接收个人 agent 的行为数据，也接收总库侧的课程结构，从而输出：

- 学习风格
- 掌握分布
- 薄弱知识点
- 推荐建议
- 风险预警

### 5.4 资源推荐 agent 的闭环作用

资源推荐 agent 处在“画像输出”和“学习行为输入”之间，负责把抽象画像转成可执行的多模态推荐：

- 将薄弱知识点映射为具体资料和练习
- 将学习风格映射为不同媒介的资源组合
- 将课程周次映射为当前最优学习顺序
- 将群体高频难点映射为优先补强内容
- 将文本问题映射为对应的图示、视频片段或例题截图
- 将推荐结果回写到个人学习树，形成下一轮学习输入

### 5.5 工具与 agent 之间的数据流

工具层不是被动执行层，而是 agent 的“感知器官”和“执行器官”。它和 agent 之间的数据流分为四类。

#### 5.5.1 agent -> 工具

agent 会向工具层发送明确的任务指令，例如：

- 解析文件
- 创建图谱
- 检索知识
- 读取 syllabus 或 personal syllabus
- 写回历史、掌握度或推荐结果

这些指令通常带有目标对象、筛选条件、周次范围、用户 ID、图谱 ID 或文件 ID。

#### 5.5.2 工具 -> agent

工具执行后会把结果返回给 agent，作为下一步推理输入：

- 文档解析结果：Markdown、三元组、知识片段
- 检索结果：paragraphs、reasoning_paths、匹配资源
- 文件结果：file_id、路径、文件名、上传时间
- 图谱结果：graph_id、graph_name、绑定关系
- 状态结果：job 状态、处理进度、失败原因

#### 5.5.3 agent -> 工具的二次控制

如果工具返回结果不完整，agent 会继续发起二次控制：

- 检索不到时调整查询词
- 解析失败时切换备用解析器
- 推荐结果不足时扩大候选资源范围
- job 失败时触发暂停、重试或结束

#### 5.5.4 工具输出对 agent 的影响

工具输出会直接改变 agent 的行为策略：

- 检索质量高，agent 更偏向精细推荐
- 检索质量低，agent 更偏向通用补充解释
- 文件和图谱绑定完整时，agent 可以做精确资源定位
- 处理失败或缺失时，agent 需要回退到保守推荐或人工提示

## 6. 前后端数据流

### 6.1 前端到后端

前端主要通过 JSON 接口传输以下数据：

- user_id
- syllabus_id
- graph_id
- file_id
- question
- learning_records
- answer_records
- resource_usage

### 6.2 后端到前端

后端主要返回：

- 课程状态
- 个人 syllabus
- 问答结果
- 图谱与 job 状态
- 学习画像
- 推荐结果
- 资源推荐清单

### 6.3 数据回写路径

- 提问结果写入 history
- 掌握度写回 personal syllabus JSON
- syllabus 更新后同步到相关 personal syllabus
- job 状态写回 MySQL
- 文件信息写回 file 表

## 8. 接口映射

- 文件上传：`/api/file_upload`、`/api/file_upload_calendar`
- 图谱创建：`/api/job_graph_create`
- job 创建：`/api/job_create`
- syllabus 构建：`/api/syllabus_build_draft`、`/api/syllabus_build`
- 个人学习初始化：`/api/learning_init_personal_syllabus`
- 问答：`/api/learning_ask_question`
- 个人 syllabus 查询：`/api/learning_personal_syllabus_detail`
- 学习画像：`/api/user_learning_profile`
