# 用户画像实验计划

## 0. 说明

本计划用于给 `learning_profile_agent_workflow.md` 提供前置实验支撑。

当前阶段不适合直接启动“大一统画像大实验”，原因是：

- 画像链路还处于设计和接口收口阶段
- 输入来源尚未完全接通
- 持久化策略和 Agent orchestration 还未稳定

因此本计划采用**多个小实验**的方式推进。每个小实验都按统一范式记录：

- 实验准备
- 数据来源
- 实验记录
- 实验结论

这样更适合边开发边验证，也更方便后续把结论回填到设计文档。

## 1. 实验总目标

本批实验主要回答四类问题：

1. 画像输入字段在真实数据里是否可得
2. 哪些输入对画像结果最关键
3. 当前画像输出是否基本稳定、可解释
4. 后续 Agent 化后，哪些能力可以保留为规则/函数，哪些值得交给 LLM

## 2. 小实验 A：输入可得性盘点

### 实验准备

- 明确统计对象：
  - `dialogue_text`
  - `learning_goal`
  - `learning_records`
  - `answer_records`
  - `resource_usage`
- 明确统计口径：
  - 字段是否存在
  - 字段是否为空
  - 可直接使用的比例
  - 需要补齐或清洗的比例
- 输出形式建议：
  - 一份字段缺失率表
  - 一份典型脏数据样例表

### 数据来源

- 当前库内已有的历史问答、学习行为、答题记录、资源使用记录
- 如真实数据不足，可补充 20 到 50 条人工构造样本
- 所有样本需脱敏后保存

### 实验记录

- 记录每类字段的样本总量
- 记录缺失率、空值率、异常格式率
- 记录时间字段格式分布：
  - 时间戳
  - ISO 时间串
  - 其他非标准格式
- 记录 `knowledge_points` 是否齐全

### 实验结论

预期得到：

- 哪些字段可以视为“稳定可得”
- 哪些字段只能作为可选增强输入
- 画像接口第一版哪些字段缺失时需要降级

## 3. 小实验 B：字段贡献度/消融实验

### 实验准备

- 选取一批带相对完整输入的数据样本
- 固定同一版画像计算逻辑
- 设计多组输入组合进行对照：
  - 全量输入
  - 去掉 `dialogue_text`
  - 去掉 `answer_records`
  - 去掉 `resource_usage`
  - 去掉 `learning_records`
  - 只保留 `user_id + syllabus_id`

### 数据来源

- 小实验 A 中筛出的高质量样本
- 建议样本量：
  - 初版 20 条
  - 稳定后扩到 50 条

### 实验记录

- 记录每组输入下的关键输出变化：
  - `knowledge_mastery.overall_score`
  - `concept_gaps`
  - `dropout_risk`
  - `recent_anomaly`
  - `confidence`
  - `evidence`
- 记录哪些字段变化最大
- 记录哪些字段在缺少某类输入时明显失真

### 实验结论

预期得到：

- 哪些输入是画像主信号
- 哪些输入是增强信号
- “全量特征直接提交”是否明显优于筛选提交
- 后续 Agent 是否有必要先做特征筛选

## 4. 小实验 C：结果稳定性实验

### 实验准备

- 选取同一批样本重复运行多次
- 若涉及 LLM 判定，保持同一模型、同一 prompt、同一温度配置
- 每个样本建议重复运行 3 到 5 次

### 数据来源

- 小实验 A、B 中已经清洗过的样本

### 实验记录

- 记录重复运行后的波动字段：
  - `goal_clarity`
  - `term_familiarity`
  - `emotion_state`
  - `dropout_risk`
  - `confidence`
  - `evidence`
- 区分：
  - 分数字段波动
  - 枚举标签波动
  - 文本证据波动

### 实验结论

预期得到：

- 哪些字段是稳定的
- 哪些字段有轻微波动但可接受
- 哪些字段不适合直接持久化为长期结论

## 5. 小实验 D：人工复核实验

### 实验准备

- 从已有样本中抽取 20 到 30 条
- 设计人工复核维度：
  - 是否符合输入事实
  - 是否有明显误判
  - 证据是否能支撑结论
  - 风险判断是否过度

### 数据来源

- 来自小实验 B 的全量输入结果
- 如有需要，可补充边界样本：
  - 仅有行为数据
  - 仅有答题数据
  - 对话信息很强但答题数据很弱

### 实验记录

- 人工为每条样本记录：
  - 合理
  - 基本合理
  - 可疑
  - 明显不合理
- 重点标记问题字段：
  - `concept_gaps`
  - `knowledge_mastery`
  - `evidence`
  - `dropout_risk`

### 实验结论

预期得到：

- 当前输出是否已经具备“可展示”基础
- 哪些字段需要继续压缩或弱化
- 哪些解释文本需要改成更保守的表达

## 6. 小实验 E：Agent 化拆分实验

### 实验准备

- 以 `learning_profile_agent_workflow.md` 为骨架
- 把当前链路拆成若干步骤：
  - 上下文读取
  - 事件归一化
  - 对话特征计算
  - 行为特征计算
  - 答题特征计算
  - 风险与证据汇总
- 对每一步判断更适合：
  - 规则函数
  - 现有 task/repo 函数
  - LLM tool calling

### 数据来源

- 不依赖大规模数据
- 主要基于已有函数、脚本样例和少量真实样本

### 实验记录

- 记录每一步的输入输出结构
- 记录是否存在明显副作用
- 记录是否容易包装成只读 tool
- 记录是否必须依赖 LLM 语义判断

### 实验结论

预期得到：

- 后续 Agent orchestration 的最小 tool 列表
- 哪些能力先不要暴露成 tool
- 哪些字段仍应由规则函数保证稳定性

## 7. 建议实验顺序

建议按下面顺序推进：

1. 小实验 A：输入可得性盘点
2. 小实验 B：字段贡献度/消融实验
3. 小实验 D：人工复核实验
4. 小实验 C：结果稳定性实验
5. 小实验 E：Agent 化拆分实验

原因：

- 先看有没有数据
- 再看哪些数据值钱
- 再看输出像不像样
- 最后再决定 Agent 怎么接

## 8. 产出物建议

本目录建议后续逐步补充：

- `experiment_plan.md`
- `samples/`
- `records/`
- `outputs/`
- `summary.md`

其中：

- `records/` 记录每次实验的原始观察
- `outputs/` 记录统计表、对比结果、可视化
- `summary.md` 汇总适合回填到正式设计文档的结论

## 9. 当前建议

如果只能先做一轮最小验证，优先做三件事：

1. 输入可得性盘点
2. 字段贡献度/消融实验
3. 人工复核实验

这三项最能直接支撑后续文档和接口设计。
