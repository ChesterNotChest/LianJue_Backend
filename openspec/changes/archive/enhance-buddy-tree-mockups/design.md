## Context

当前 `frontend-portal-redesign` 的 SVG mockup 中，学伴仅被表达为右下角 FAB 按钮 + 简单标签。后端 `study_buddy` 模块的完整六层能力在视觉稿中不可见。`05-learning-tree.svg` 过度依赖 D3 力导向图表达知识差距，后端 `BuddyTree` 的 `explore` regions、`buddy_notes`、`summary` 等丰富文本字段未被利用。

本设计聚焦于"在不新增后端能力的前提下，将已有数据字段在 SVG mockup 中以文字信息区形式充分表达"。

## Goals / Non-Goals

**Goals:**
- 05-learning-tree.svg：图谱下方新增文字分析区——待探索知识列表（差了什么）、学伴节点观察、综合建议
- 04-agent.svg：扩展右侧面板，展示 BuddyDrawer 滑出态（完整聊天流 + 记忆标签写入）
- 表达学伴的标签式记忆（buddy_memory tags）— 在 05 中可视化"小觉记住了什么"
- 表达节点观察（buddy_notes）— 在 05 中以学伴感受卡片形式展示
- 图谱保留但缩小，为文字区腾出空间

**Non-Goals:**
- 不新增后端 API 端点
- 不修改数据模型或 BuddyTree schema
- 不新建 SVG 文件（在现有文件中修改）
- 不改变 05 的 D3 图形渲染逻辑（仅调整 SVG 中的视觉表达）

## Decisions

### Decision 1: 05 页面布局重构

```
旧布局 (1100px高):
┌──────────────────────────────┐
│ 顶栏 + 侧栏                   │
├──────────────────────────────┤
│ 统计条                        │
│ D3 图谱 (880×400)             │
│ Gap 总结 (1行)                │
│ 学伴消息 (1行)                │
│ (大量空白)                    │
└──────────────────────────────┘

新布局 (~1300px高):
┌──────────────────────────────┐
│ 顶栏 + 侧栏                   │
├──────────────────────────────┤
│ 统计条                        │
│ D3 图谱 (880×320, 缩小20%)    │
├────────────┬─────────────────┤
│ 薄弱点分析  │  待探索知识列表   │
│ (4卡片)    │  (6项,含摘要+关联)│
├────────────┴─────────────────┤
│ 学伴的观察 (buddy_notes 卡片)  │
│ 学伴的记忆 (memory tags 云)    │
│ 小觉的综合建议 (2-3句话)       │
└──────────────────────────────┘
```

**Rationale**: 图谱下的空白浪费了 300px+ 空间。用文字卡片填满信息密度，评审核一眼看到"这页有数据、有分析、有建议"。

### Decision 2: 待探索知识列表的数据映射

从 `BuddyTree.regions.explore` + `nodes[].{summary, buddy_notes, associated_trunk}` 中提取：

| SVG 展示字段 | 数据源 |
|-------------|--------|
| 知识点标题 | `nodes[nid].title` |
| 摘要说明 | `nodes[nid].summary` (前80字) |
| 关联主干 | `nodes[nid].associated_trunk` → 匹配 trunk titles |
| 学伴感受 | `nodes[nid].buddy_notes[last].note` (最新一条) |
| 掌握度 | `nodes[nid].mastery.label` + `score` |

Mockup 中使用 Chester 算法设计与分析课程的示例数据（与现有 SVG 一致）：
- 减治法、BFS、贪心策略、后缀树、网络流、分支限界 → explore region

### Decision 3: BuddyDrawer 展示位置

在 04-agent.svg 中，将右侧面板底部（当前为知识库搜索折叠态）改为 BuddyDrawer 展开态：

```
04-agent 右侧面板 (296px宽):
┌─────────────────────┐
│ 学习计划 (保留)      │
├─────────────────────┤
│ 学伴小觉 (BuddyDrawer)│
│ ┌─────────────────┐ │

│ │ "RowKey资料好了"  │ │
│ │                  │ │
│ │ [你] 能帮我看看?   │ │
│ │ [小觉] 这篇挺短的  │ │
│ │  先扫一眼就行~    │ │
```

**Rationale**: 04-agent 右侧面板高度充足（~800px），当前底部为折叠态浪费空间。展开 BuddyDrawer 既展示学伴对话能力，又不增加新页面。

### Decision 4: 学伴记忆可视化

在 05 页面底部的"学伴的记忆"区域，以 tag 云形式展示 `buddy_memory.jsonl` 中的标签：

```
学伴的记忆 — 小觉关于你的笔记
┌──────────────────────────────────────────────────────────┐
│ [RowKey 热点反复挫败] [喜欢短文档胜过视频] [DFS 时容易放弃]   │
│ [分治策略掌握扎实] [考试前会紧张] [需要更多实操练习]          │
└──────────────────────────────────────────────────────────┘
```

表达"学伴会记住你的学习模式"这一关键差异化能力。

### Decision 5: 节点观察表达为学伴感受

buddy_notes 是学伴对特定知识节点的观察，存储在 tree.json 中。在 SVG 中表达为"小觉的感受"：

```
学伴的观察 · 小觉对节点的感受
┌──────────────────────────────────────────────────────┐
│ 📝 "DFS" — 嘴上说理解了但做题总在回溯时出错            │
│    记于 2026-07-15 · mastery_hint: weaker             │
├──────────────────────────────────────────────────────┤
│ 📝 "分治策略" — 实际理解比分数深，能讲清楚归并排序原理   │
│    记于 2026-07-14 · mastery_hint: stronger            │
└──────────────────────────────────────────────────────┘
```

表达学伴的"观察者"角色——不只是被动回复，而是主动记录对学生的理解。

## Risks / Trade-offs

- **SVG 高度增长**: 05 从 1100px → ~1300px，04 从 1200px → ~1300px。风险低——mockup 不限制实际页面高度，SVG viewBox 支持任意高度。
- **文字内容需手写**: 后端有真实数据但 mockup 是静态 SVG。需根据 Chester/算法设计与分析 的示例数据手写合理的 buddy_notes 和 memory tags。不追求与真实 LLM 输出一致，追求"看起来真实"。
